# Shin4Static

Маршрутизация выбранных сетей через VPN на Keenetic с Entware: по своим
спискам (IP, подсети, диапазоны, домены, номера AS) и с kill switch для
отдельных записей. Подробности и причины решений — в [DESIGN.md](DESIGN.md).

## Установка

```
opkg install git git-http
git clone https://github.com/shinleinen-dotcom/Shin4Static.git
sh Shin4Static/install.sh
```

Повторный запуск `install.sh` обновляет код и сохраняет настройки и списки.
Удаление: `sh Shin4Static/uninstall.sh` (с `--purge` — вместе с настройками).

Shin4Static работает своим экземпляром BIRD и не трогает `/opt/etc/bird.conf`
и системный `bird`: процессы, конфиги и таблицы Bird4Static и Shin4Static
независимы. Но правила Bird4Static (приоритеты 30020–30022) проверяются раньше
наших: если сеть есть в его списках, путь выбирает Bird4Static, и `!KS0`
Shin4Static для неё не сработает. `shin4static status` показывает такие правила.

Только IPv4: домены и AS дают IPv4-адреса, kill switch тоже только для IPv4.
Если провайдер выдаёт IPv6, клиенты могут ходить к тем же сервисам по IPv6
мимо VPN — отключите IPv6 для клиентов или у подключения к провайдеру.

## Списки

`/opt/etc/shin4static/lists/isp.list`, `vpn1.list`, `vpn2.list` — по одной
записи на строку:

```
2ip.ru                  # через VPN1, при его падении — через провайдера
!KS0 AS555842           # только через VPN1, при падении — блок
!KS2 203.0.113.0/24     # VPN1, затем VPN2, затем блок
!FB2 198.51.100.0/24    # VPN1, затем VPN2, затем провайдер
```

После правки списков:

```
shin4static check       # проверить, ничего не меняя
shin4static update      # применить (cron делает это раз в час)
```

## Диагностика

```
shin4static status      # интерфейсы, правила, таблицы, последний запуск
shin4static why 1.2.3.4 # в какую группу входит адрес и куда он идёт сейчас
```

## Веб-интерфейс

Установщик предлагает его включить: свой экземпляр lighttpd из Entware на
адресе роутера в локальной сети (по умолчанию порт 8088). Стандартный lighttpd
(`S80lighttpd`, `/opt/etc/lighttpd/`) не используется.

Вход — на выбор при установке:
- **паролем роутера** (`WEB_AUTH=router`, по умолчанию): логин и пароль от
  веб-интерфейса Keenetic. Shin4Static проверяет их запросом к `/auth` роутера
  и пароль не хранит; пускаются только пользователи из `WEB_USERS`
  (по умолчанию `admin`), сессия живёт `WEB_SESSION_TTL` (12 часов без действий);
- **отдельным паролем** (`WEB_AUTH=local`): логин `admin`, хэш в
  `/opt/etc/shin4static/web.htdigest`. Если роутер не отвечает на `/auth` как
  ожидается, установщик выбирает этот вариант сам.
Списки показаны блоками: комментарий `# …` над строками — заголовок блока,
пустая строка — граница. У каждой записи свои флажок KS, выбор резервного VPN
и заметка; KS и резерв можно задать сразу всему блоку. Отмеченные записи
переносятся в новый или существующий блок. Режим «Текст» показывает файл как
есть. На диске формат прежний — генератор и cron ничего не замечают.

Ещё можно проверять, применять, смотреть состояние и спрашивать, куда идёт
адрес. Клик по `vpn1.list:7` в выводе подсвечивает нужную запись.

Защита: сервер слушает только адрес в локальной сети, клиенты — только из
`WEB_ALLOW` (по умолчанию сеть `br0`, гостевая сеть не пускается; проверяют и
lighttpd, и CGI), пароль, токен против CSRF (новый при каждом запуске),
изменяющие запросы и вход — только со своей страницы (Origin), проверка
заголовка Host против DNS rebinding (имена кроме IP — в `WEB_HOSTS`), запись
только в файлы списков. При входе паролем роутера пароль не уходит из
браузера: как и страница входа Keenetic, она отправляет только хеш. После трёх
неверных паролей каждая попытка ждёт на 30 с дольше. Если файл списка изменили
в другой вкладке или по SSH после загрузки страницы, сохранение отказывает, а
не затирает чужие правки.

Запуск и остановка: `/opt/etc/init.d/S81shin4static-web start|stop|status`.
Сменить способ входа или отдельный пароль: очистить `WEB_LISTEN=` в
`shin4static.conf` и запустить `install.sh`.

## Тесты

- `sh tests/run.sh` — генератор; нужны `iprange` и доступ к DNS. curl, birdc и
  ip подменяются заглушками, роутер не нужен.
- `sh tests/cgi.sh` — веб-API.
- `bash tests/web.sh` — настоящий lighttpd через `S81shin4static-web`
  (`LIGHTTPD=…`, `LIGHTTPD_MODULES=…`, если он не в `/usr/sbin`).
- `node tests/model.test.js` — разбор и сборка файла списка в блоки, MD5 и
  SHA-256 для входа.
- Просмотр интерфейса на Windows с WSL: `sh tests/devroot.sh` в WSL, затем
  `python tests/devserver.py` и http://127.0.0.1:8099/.
